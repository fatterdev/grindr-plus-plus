## TL;DR

1. Play app details still report **tip 194910 / 26.23.0**, but an explicit delivery
   request for **195444 / 26.24.0** is served (3 files, Play-signed).
2. The `px_9a` (SDK 35) variant is **minSdk 32**; it is suitable for the
   Android 15 A2 Lite, not for the Android 10 P30.
3. `--ei version_code 195444` does **not** reach `getLongExtra`; the probe kept
   its default 187695. Use `--el version_code 195444` (long extra). The 187695
   run never exposed this because 187695 was also the probe default.
4. JADX produced 39 232 classes with 91 885 errors; the sources are still
   sufficient for the fingerprint remap, but JADX misses some classes (e.g.
   `kdg`). DEX descriptors are the class-existence ground truth.
5. The 194910 short R8 names are **not reusable**: `tpv`, `frv`, `nna`, `ona`
   and `kdg` exist on 195444 but are different classes. The pack uses
   fingerprints/FQCNs and explicit soft-skips; 40/85 symbols are named.
6. `libpairipcore.so` and `libsqliteJni.so` differ from 194910 (SHA-256 below),
   so the 194910 native decrypt pack cannot be reused.

### Lab finding: int vs long extra

`GplayProbeActivity` reads `intent.getLongExtra(EXTRA_VERSION_CODE, 187695)`.
`am start --ei` stores an int, so `getLongExtra` returns the default. The
187695 track was masked by the default. Use `--el` for future probes; a
debug-only fix should accept both types.

### Why names were not copied

A plain name-presence check found 41/42 old names in the 195444 DEX, but the
classes are different:

| Old (194910) | Old role | 195444 class with same name | Actual 195444 role |
|---|---|---|---|
| `tpv` | user agent | `tpv` | Gson factory |
| `frv` | UserSession | `frv` | collection utility |
| `nna` | Retrofit `Fail` | `nna` | two-field model |
| `ona` | Retrofit `Success` | `ona` | synthetic lambda |
| `kdg` | feature-flag evaluator | `kdg` | UI/state class |

The generator therefore treats short R8 names as untrusted. FQCNs are kept
only when the DEX descriptor exists; every other symbol needs a unique
fingerprint or is soft-skipped.

### Soft-skips (explicit, not silent)

- `FeatureGranting.isFeatureFlagEnabled` / `CloneLoginCompat.isFeatureFlagEnabled`
  (`kdg` on 194910): the 195444 feature-flag API changed; the old name is a
  different class. `CloneLoginCompat` is marked `skipped`.
- `ProfileDetails.PROFILE_BAR_VIEW`: `ProfileBarView` is absent on 195444.
- `QuickBlock.blockViewModel`: no fingerprint; unresolved.
- `WebSocketAlive.FACTORY`: unresolved; client FQCN is mapped.
- `core.serverDrivenCascadeRepo`: `CascadePage` no longer present.

Hooks are `unverified` (or `partial`/`skipped` with reasons); the pack does
not claim runtime success. E2E on the 195444 clone is the next step.

## Validation

```text
python scripts/validate_mapping_packs.py --require-tip
```

The 195444 pack is added to `mapping-packs/index.json`. The
`install-availability.json` row is **deferred**: the validator requires
`pairip: true` rows to use `patch: "mapping+pairip"` and to have a
`pairip-decrypt/195444/pack.json`, which does not exist yet. `latest_play.json`
stays at 194910 because Play still reports 194910 as the tip. The pack is
**not** copied into `app/src/main/assets/mappings/` yet, so the Manager's
bundled pack preference does not silently switch to an unvalidated 195444.
