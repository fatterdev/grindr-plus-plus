# PairIP phase 3 — Grindr 26.24.0 / 195444 native pack

- **Date:** 2026-11-12
- **Branch:** `pairip/195444-pack` (from `master` @ `32cb644`)
- **Device:** Mi A2 lite (`17a3c47f0305`), LineageOS 22 / Android 15, arm64, root
- **Host:** Play 26.24.0 / `versionCode` 195444 (Play delivery, `installerPackageName=com.android.vending`)
- **Status:** native decrypt pack produced and validated from a **Play-signed stock** RX dump. Clone E2E is **not** done; no bypass is claimed.

## TL;DR

1. `libsqliteJni.so` 195444 differs from disk in exactly **50 933 bytes / 188 ranges**,
   first `0x48778`, last `0x54f27`, RX size `0xb46f8`; `libpairipcore`, crashlytics and
   datastore controls diff **0**. This matches the static prediction (`0x48778..0x54f28`).
2. The pack is assembled from the **195444 disk shell + the dumped RX block**
   (`pairip-decrypt/195444/`, SHA-256 `ffc4ca0f…`). The 194910 pack is **not** reusable:
   its decrypted block differs from 195444 in 685 958 / 739 064 bytes.
3. Stock 195444 on the rooted A2 Lite **crashes under Vector/LSPosed injection** at
   `libpairipcore+0x6ef60` (SEGV_ACCERR, fault `0x7027bc2ce0`). Adding
   `com.grindrapp.android` to the Magisk denylist makes stock reach `LoginActivity`.
   This is a framework confound, not a 195444 regression.
4. Frida on stock 195444 is detected: SIGSEGV at `libpairipcore+0x2a34c`
   (fault `0x200000008`) after ~9 s. The Frida harness is ready, but stock 195444
   needs anti-detection/denylist work; the successful dump used root `/proc/<pid>/mem`
   with no Frida.
5. The `pairipfix` LSPosed module is **incompatible** with 195444:
   `ClassNotFoundException: com.pairip.licensecheck.ResponseValidator`, then the same
   `0x6ef60` crash. It was uninstalled.
6. Mapping pack refined to **45/85 named symbols** (40 soft-skips). `FeatureGranting` /
   `CloneLoginCompat` resolve to `qtg`; `QuickBlock` / `ProfileDetails` view-based hooks
   are gone (Compose), so they are documented as skipped rather than guessed.

## 2. Stock Play install and framework confound

The A2 Lite's existing stock 26.16.1 was adb-installed and had no Play license record.
Installing 195444 with `adb install-multiple` reproduced the license gate and the process
exited before AndroidX loaded `sqliteJni`.

The clean path was:

1. uninstall the adb-installed stock;
2. install 195444 from the Play Store on the A2 Lite (Play-signed, licensed);
3. add `com.grindrapp.android` to the **Magisk denylist**:
   `su -c 'magisk --denylist add com.grindrapp.android'`;
4. launch `com.grindrapp.android/.HomeActivityOriginal`.

Without the denylist, stock 195444 crashed at `libpairipcore+0x6ef60`
(`SIGSEGV`, `SEGV_ACCERR`, fault `0x7027bc2ce0`); with the denylist it reached
`LoginActivity` and stayed alive. The A2 Lite has both `zygisk_vector` and
`zygisk_lsposed`; either framework's injection is enough to trip PairIP.

The Play install has splits `base + config.arm64_v8a + config.it + config.xxhdpi`.
The installed arm64 split SHA-256 is `963497581d18bc085981f365f81a9fda71cd8664add98b00af8c734379886d42`,
identical to the `px_9a` delivery used for the pack.

- skip `am force-stop`/`am start` when the launch component is `none`;
- always attempt dump pass 1 (gated stock can exit between `find_pid` and the first pass).

```text
python scripts/pairip_dump_libs.py --version-code 195444 \
  --split tmp-grid-lab/pairip-195444/installed-arm64.apk \
  --out  tmp-grid-lab/pairip-195444/dump-stock-195444-play \
  --no-launch --serial 17a3c47f0305
```

Result (`report.json`):

| lib | disk SHA-1 | diff | note |
|---|---|---:|---|
| `libsqliteJni.so` | `5125bb9226e83428de66fd392956e2174d24bbb6` | **50 933 B / 188 ranges** | `0x48778..0x54f27` |
| `libpairipcore.so` | — | 0 | plaintext on disk and in memory |
| `libcrashlytics*.so`, `libdatastore_shared_counter.so` | — | 0 | controls |

The dump's `libsqliteJni.so.mem.bin` is a full-size buffer with only the RX region

Pack layout:

```text
pairip-decrypt/195444/
  pack.json
  libsqliteJni.so          # disk shell + decrypted RX
  libsqliteJni.so.rx.bin   # dumped RX block (739 064 B)
```

`pairip_diff_ranges.py` against the 195444 disk lib: **188 ranges, 50 933 bytes**.
The 195444 decrypted RX differs from the 194910 pack in 685 958 / 739 064 bytes, so the
plaintext is **not** build-independent and a 195444 dump was mandatory.

## 4. Frida and `pairipfix` confounds

- **Frida** (`trigger_sqlite.js` + `pairip_probe.js`): stock 195444 crashed at
  `libpairipcore+0x2a34c` (`SIGSEGV`, fault `0x200000008`) after ~9 s. The probe's
  `JNI_OnLoad`/`executeVM` hooks were installed, but the process died before
  `sqliteJni` could be triggered. This is anti-Frida/native tamper, not a clone result.
- **`pairipfix`** (LSPosed module, `io.github.ahmedmani.pairipfix`): the module loaded
  under Vector but failed with
  `ClassNotFoundException: com.pairip.licensecheck.ResponseValidator`, then the same
  `0x6ef60` crash. It is not compatible with 195444; uninstalled.
- **Magisk denylist** is the working stock path: it excludes the app from
  Vector/LSPosed injection and lets the Play-signed app run.
